# 실제 기기 확인 기록

- 날짜: 2026-11-24 (한국 시간).
- APK: NetRobot Drone v0.1.0, `com.netrobot.drone`.
- Wi-Fi: 사용자가 제공한 `FLOW_27AF9C`.
- 기존 카메라 앱: WiFi UAV.
- 결과: 사용자가 이 채팅에서 APK를 연결하자 드론 카메라 영상이 보인다고 확인함.
- 확인 범위: 드론 영상 수신. 해상도, 지연, FPS, 장시간 재접속은 측정하지 않음.
- 휴대폰/드론의 정확한 모델명: 미제공.
- 그물 탐지: 이 시점 v0.1.0에는 학습 모델이 없었으므로 확인한 기능이 아님.
- 로봇 모터: 실물 미연결, 모의 조종.

자동 승인 검토가 Android 에뮬레이터 시스템 이미지 설치 명령을 정책상 차단했으므로 에뮬레이터 실행 검증은 하지 못했습니다. APK 빌드·서명·소프트웨어 검사와 위 사용자 보고는 별개로 기록합니다.

## v0.2.0 소프트웨어 확인 (2026-11-25)

기본 디자인의 800×400 가로 화면에서 조종 연습·집게 상태 변경·로봇 숨기기·감지 끄기를 확인했습니다. Chromium 브라우저에서 실제 640 ONNX 모델 불러오기·초기 추론·IndexedDB 저장·페이지 재실행 후 모델 복원을 확인했습니다. APK 내 WASM과 PyTorch 수치 비교도 통과했습니다. Android에서 v0.2.0을 실행한 검증은 아직 하지 못했습니다.

## v0.3.0 소프트웨어 확인 (2026-11-25)

직접 작성한 화면 동작을 Brython Python으로 통합했습니다. Chromium에서 연습 화면·집게·모델 파일 불러오기·초기 추론·IndexedDB 저장·재실행 복원을 확인했습니다. 조이스틱/모터 계산, YOLO 좌표/중복 제거, GitHub 프로젝트 주소 제한, UDP 조각/JPEG 복원 자동 검사를 통과했습니다. 기존 그물 가중치는 변경하지 않았습니다.

별도 localhost 검사 서버에서 실제 검증 사진 2185를 가상 영상 API로 전달해 영상 표시부터 추론·박스·신뢰도 출력까지 확인했습니다. 이는 실물 드론 연결 검사가 아닙니다. Brython 캔버스의 CSS 크기와 실제 픽셀 크기를 구분해 설정하도록 수정했고, 버튼을 놓으면 집게가 대기로 돌아오는 것을 확인했습니다.

앱은 GitHub 프로젝트 URL을 열고 HTML/Python 버전과 해시가 맞을 때 온라인 소스를 사용하며, 실패하면 APK 내 사본을 사용합니다. 인터넷 상태/불일치/오프라인 분기는 PC에서 실제 함수와 임시 응답으로 검사합니다. Android 전용 Wi-Fi 바인딩과 WebView의 새 버전 실행은 실물에서 확인해야 합니다. APK 빌드·서명·내부 자원 검증은 실행 검증과 구분합니다.

## 웹 조종 화면 v4 (2026-11-25)

APK 다운로드 버튼과 설치 안내를 사이트에서 제거하고 처음부터 조이스틱·집게·로봇 모형을 조작하도록 변경했습니다. 동일한 기존 그물 가중치를 웹 자원에 포함해 자동 로드합니다. 실제 검증 사진과 해당 사진을 반복한 검사 영상에서 브라우저 내 감지·박스·점수 표시를 확인했습니다. 검사 영상은 학습 데이터가 아닙니다.

Python HTTP 수신부의 응답과 접근 제한은 자동 검사로 확인했습니다. FLOW UDP의 실제 기기 연결은 이전 수신부를 재사용하지만 새 웹/휴대폰 구성의 실기 연결을 확인한 것은 아닙니다. GitHub 사이트에 접속하는 것만으로 UDP 영상을 받는다고 표시하지 않습니다.

## OpenCV·앞바퀴 2개·SG90 전환 (2026-11-25)

실제 ONNX를 Python OpenCV DNN으로 실행하고 검증 사진에서 박스와 점수의 JPEG 출력을 확인했습니다. 브라우저에서 사진 프레임을 로컬 서버로 보내 OpenCV 결과를 표시했고, 로봇/뒷바퀴 그림을 제거했습니다. 자동 검사 16개가 통과했습니다. 모델 가중치는 변경하지 않았습니다.

UNO는 COM11에서 업로드와 검증을 완료했습니다. UART 속도 자동 확인과 USB 부팅 진단을 추가한 스케치도 업로드 검증했으며 USB에서 READY 메시지를 확인했습니다. HC-06은 Windows 페어링과 COM13을 확인했습니다. 다만 현재까지 Bluetooth에서는 펌웨어 응답 없음 또는 포트 열기 오류 121이 발생해 실제 제어 연결 성공으로 기록하지 않습니다. 실제 ARM·회전·집게 움직임 명령은 보내지 않았습니다. USB 부팅 성공과 Bluetooth 데이터 통신 성공을 구분합니다.

한글 바탕화면 경로의 모델을 OpenCV 파일명 API로 열지 못하는 문제를 파일 바이트 입력으로 수정했고 실제 한글 경로 검사를 추가했습니다. 현재 로컬 조종 주소는 http://127.0.0.1:8770/?bridge=1 입니다.

## Arduino USB 실제 통신 성공 (2026-11-25)

COM11에 USB/HC-06 겸용 스케치를 업로드하고 플래시 검증했습니다. Python MotorLink로 실제 UNO의 NETROBOT 1 인사와 STOPPED 정지 응답을 확인했습니다. USB 연결 뒤에도 armed=false, 좌우 출력 0을 확인했습니다. 실제 ARM·회전·서보 이동 명령은 보내지 않았습니다. 자동 검사는 17개입니다.

HC-06은 새 Bluetooth 검색에서 현재 시각의 응답을 확인했지만, COM13 오류 121과 직접 SPP 서비스 연결 오류 10060이 발생했습니다. 무선 발견 성공과 데이터 연결 실패를 구분합니다.

## 집게 범위와 명령 속도 변경 (2026-11-25)

사용자 요청에 따라 집게 명령을 0~180도, 10ms마다 6도로 변경하고 COM11 업로드·검증을 완료했습니다. 이전 70~110도, 30ms마다 1도와 구분합니다. 실제 기구의 도달 각도·부하 시 속도를 측정한 결과는 아닙니다. DC모터는 이미 PWM 255 최대 출력이므로 더 높은 PWM 값을 보내지 않습니다.
